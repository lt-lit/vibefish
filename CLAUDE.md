# Vibefish — Claude Code context

Read `DESIGN.md` first. This file is the short version plus hard constraints.

## What this repo is
Commander deck playtesting engine built on Forge's headless `sim` mode. Engine only — decks, playbooks and results live in a separate data repo and are passed in by path. `demo-data/` holds the public pod results the dashboard shows.

## Hard constraints
- **Dashboard:** vanilla JS, no build step, no TypeScript, no frameworks. Must work on GitHub Pages and on a phone browser. It reads only the data contract in `DESIGN.md` §6 (`index.json`, `rollup.json`, `cards/scryfall-cache.json`, and the optional `bots.json`).
- **Images:** never commit card image files. Hotlink `cards.scryfall.io` URLs from the cache only; `small` and `normal` only, never cropped art.
- **Scryfall API:** ≥100 ms between requests to `api.scryfall.com`; set `User-Agent: Vibefish/<version>` in scripts (`runner/scryfall.py` does); leave browser UA alone in page JS. Resolve names in batches via `cards/collection`.
- **Forge:** pinned to the tag in `forge/VERSION` with the checksum in `forge/SHA256SUMS`. Do not float to `latest` or `daily-snapshots` unless `FORGE_CHANNEL=snapshot` is explicitly set; a snapshot build that published runs depend on is pinned exactly with `FORGE_SNAPSHOT_BUILD=<build>` and its checksum recorded in `forge/SHA256SUMS` (the 2026-11-08 and 2026-11-10 builds are). The runtime is downloaded by `forge/fetch-forge.sh` into `forge/runtime/` and is never committed. Forge's `daily-snapshots` release holds one tarball at a time, so a pinned snapshot can be fetched from upstream only until the next snapshot replaces it (checked 2026-11-11 16:16 UTC: the 11-10 tarball was still there, no 11-11 build yet, 11-08 and 11-09 answered 404). Snapshot builds that published runs depend on are therefore archived (decided 2026-11-11): `forge-archive.yml`, started by `runner/queue/forge-archive.json`, packs the assembled runtime and attaches it to this repository's release `forge-runtimes`; `forge/SHA256SUMS` lists the archive (`forge-runtime-snapshot-YYYY-MM-DD.tar.gz`), and `forge/fetch-forge.sh` fetches a pinned `FORGE_SNAPSHOT_BUILD` from there when it is listed. The 11-08 and 11-10 builds are archived. When a new snapshot is first used for a published run, archive it straight away (while upstream still has it or the Actions cache does) and add the checksum it prints. The Actions cache key hashes `forge/VERSION`, `forge/SHA256SUMS` and `forge/fetch-forge.sh`, so editing them makes the next run fetch again: fine for archived builds, fatal for a snapshot that is not archived yet. The archive is for reproducing published runs, not for staying on old builds: keep up with Forge (the 2.0.16 release came out on 2026-11-11 and the pin has not moved yet: Status, Next, the Forge item).
- **No Forge fork.** `controller/` compiles against the released Forge jar and uses public hooks (event bus, `PlayerControllerAi`). Patch Forge only if a hook is private, and record it in `DESIGN.md`.
- **No contact with anyone** (the owner, 2026-11-11, in so many words): the owner writes to nobody, posts nothing, forks nothing and interacts with no one for this project. Never suggest it, in any form: no emails or data requests (Playgroup included), no issues, pull requests, comments or forum posts anywhere, no forks. The project works with what is public and with what its own runs produce; the only pushes are to the owner's own repositories.
- **No upstream filing.** Forge bugs seen in runs are noted in `docs/upstream.md` for our own reference only; this project does not file Forge issues or PRs, so never suggest it.
- **Per-deck bots, not a general bot.** Custom behaviour reaches a seat only through that seat's playbook and data, written for one specific deck (a precon or a deck from the user's meta). Shared behaviour modules are fine, but they stay inert unless a deck's playbook opts in with its own parameters, and seats without a playbook run stock Forge AI, untouched, as the baseline. We are not building a generalised bot: nothing is switched on for every deck regardless of context, and Forge's default AI is not rewritten. Phase 3 data (`playbook/precons/<id>.json`, DESIGN §19) reaches a seat through the harness `--data` and that seat's profile; Forge's role and combo lists are global for a game, so only lines about the deck's own cards go in.
- **Always pass a clock** to sim mode (`-c` / `--clock`). Forge's default is 120 s and declares longer games a draw; Commander games routinely exceed it. The harness also caps turns (`--turn-cap`, default 120).
- **Event schema:** changes to the JSONL events or `run.json` keep `runner/rollup.py` and `DESIGN.md` §6 in sync and bump `VERSION`.
- **License:** this repo is GPL v3 because `controller/` compiles against Forge. Don't vendor non-GPL-compatible code.
- **Naming:** project is "Vibefish". "MTG" / "Magic: The Gathering" appear only descriptively, never in the product name, repo name, or logos.
- **Benchmark pod** in `runner/benchmark-pod.json` is frozen. Do not edit it. The **precon league** in `runner/precon-league.json` (`league-v1`, 91 decks) is frozen too: a different deck list is a new league with a new name. The same goes for the small leagues in `runner/leagues/` (`bots-v1`, the four decks with a shipped playbook on 2026-11-11; `bots-v2`, the twelve of 2026-11-12, which is the pool the exams draw opponents from now; `owners-table-v1`, the ten precons the owner's group plays, written on 2026-11-14 as the league of the owner's table and the pool a playtest of the owner's own lists draws from; `league-run` #4 and `ab-run` #42 are its first games): another list is `bots-v3` or `owners-table-v2`, a new file.
- **Human references** (`runner/reference/`): figures copied from Playgroup.gg's public pages with the retrieval date, the page and the licence noted (`playgroup-commander.json`, transcribed from one saved copy of the precon tier page by `transcribe-playgroup.py`; `playgroup-cards.json`, twelve cards' play figures read one page a card on 2026-11-11, provisional). Using them is allowed: Playgroup's legal page publishes its aggregated statistics under CC BY 4.0, to be credited with a link to the page, and its robots.txt lets crawlers read the statistics pages (DESIGN §26). Nothing in the pipeline fetches playgroup.gg: that is this project's own caution from the session that first copied the table, not something the site asks for and not a rule the owner set. The figures are context, not a yardstick for a bot (Status, What the human figures are worth): collect no more of them unless the owner asks.

Bundled Commander precons: `forge/runtime/res/quest/commanderprecons/` (179 decks named `Name [SET] [YEAR].dck`). Forge needs Java 17+ (CI uses Temurin 21). Sim mode does not need card images.

## Forge sim mode notes
Four `-d` decks in plain mode = one 4-player game (confirmed Phase 0). **Never use `-t`/`-p` for Commander:** tournament mode pairs decks 1v1 at 20 life and ignores `-D` for named decks. `-D` must be absolute; quote names with spaces. Per-seat AI profiles: `-a` in sim mode, `--profile` in the harness (`res/ai/*.ai`). Forge's AI prints a `java.util.concurrent.TimeoutException` stack trace when its own decision timeout fires; harmless. Forge's user data is redirected into `forge/runtime/profile/` by the `forge.profile.properties` the fetch script writes.

## Workflows
- `phase0.yml`: Forge sim-mode smoke test on push to `forge/**`, `runner/**`.
- `pod-run.yml` (manual): 4 shards × N games, rollup, optional publish into `demo-data/` on the branch.
- `league-run.yml` (manual, or a push to `testing` that changes `runner/queue/league-run.json`): a league in up to 20 shards (the league file, cycles, seed, Forge channel and snapshot build, profile, Monte Carlo, playbooks as inputs), rollup and scorecard, optional publish of `rollup.json`, `scorecard.json` and `league.json` into `demo-data/` on the branch. Per-game data stays in the run's artifacts. The league file is `runner/precon-league.json` (the 91 precons) unless the request names another: `runner/leagues/bots-v1.json` is the four decks with a shipped playbook as one table, and with `playbooks` every seat is a bot.
- `ab-run.yml` (manual, or by commit): paired A/Bs of per-deck data for a list of decks (tables, arms, shards per deck, `opponents` 1 for duels), one rollup per deck as artifacts; nothing is committed. A deck written `deck@name` plays the candidate playbook `playbook/variants/<deck>-<name>.json`; a candidate run with `arms: playbook` on the seed of an earlier run pairs with that run's stock arm (`ab.py join`). The queue file may hold several requests (`"runs": [{decks, arms, seed, ...}, ...]`, each with its own arms and seed, top-level fields as defaults), played as one workflow run. Runs do not wait for each other (since 2026-11-11; before that a branch ran one at a time with one waiting, and a slow last shard held up everything behind it): each push of the queue file starts its run at once and GitHub's limit on concurrent jobs paces them. A push to `testing` that changes `runner/queue/ab-run.json` (the same fields as the inputs; a new `requested` value re-runs the same request) starts it without a click; promoting to `main` starts nothing. Opponents are the league's decks under stock AI unless the request says otherwise: `pool` (a deck list, `runner/leagues/bots-v2.json`) draws them from the bot decks and `opponent_playbooks` seats each under its shipped playbook, which is the exam since 2026-11-11 (Status, How a bot is judged).
- `forge-archive.yml` (manual, or a push to `testing` that changes `runner/queue/forge-archive.json`): packs the runtime of the snapshot builds named there (from the Actions cache, or upstream while it has them) and attaches each to the release `forge-runtimes` with its checksum; commits nothing. An archive already on the release is kept as it is (published runs are pinned to its checksum); only `"replace": true` overwrites one, and `forge/SHA256SUMS` then needs the new checksum at once.
- Pages: no workflow. The `testing` branch is served as-is; a push there is live within about a minute. Workflows that are `workflow_dispatch`-only (`pod-run.yml`) can only be started once they exist on the default branch.

## Status (2026-11-21)
What it is for (the owner, 2026-11-12, DESIGN §29): playtesting new Commander decks, by simulating a great many games and, secondarily, by playing against the bots in person in Forge's desktop app. That gives a bot two jobs: the pilot of the deck under test, and an opponent whose job is not to win but to give that deck the game a table would (a clock, answers aimed at what matters, attention when it pulls ahead). The goal the owner set for the pilots: bots that play their decks the way a competent person would, one deck at a time, measured by the same deck under stock Forge AI at tables of bots and by the mistakes the logs show, not by people's win rates (What the human figures are worth, below). `DESIGN.md` has every number and the run it came from (§14 to §34); this is the short version, kept current.

**The owner's order of work (2026-11-20):** "we'll do custom decks after we have actual human level bots." The playtest of the owner's own lists (DESIGN §31) waits until the bots play at the level of a person; the pilots are the work. Do not ask for a list in reports any more. `main` was fast-forwarded to `testing` on the owner's go-ahead the same day (to 878448e) and moves again only on a new one: ask when `testing` has moved a milestone beyond it.

### Start here (written 2026-11-21 in the evening by the session of 2026-11-13, which was still running)
1. **Where the bots stand.** Twenty-two decks have a shipped playbook: the twelve of the pool and the ten precons of the owner's table. On tables that chose nothing they win 24.6% of 4,400 tables where their stock pilots win 19.2% (`ab-run` #40 and #42, DESIGN §32); the sections below have every table. ### How a bot is judged (the owner, 2026-11-11)
Not by beating a table of stock AI. The goal is a pilot that plays its deck as a competent person would; stock opponents do not punish what people punish, and it is hard to play like a person against them, so a result at their table says little about that. From here on a candidate's exam is the paired A/B at tables of bots: the deck under stock AI and under its playbook on the same tables, the three opponents drawn from the decks that have a shipped playbook (`runner/leagues/bots-v2.json` since 2026-11-12, `bots-v1.json` before) and each under it (`ab-run` with `pool` and `opponent_playbooks`; `runner/ab.py --pool ... --opponent-playbooks`). The stock arm stays as the control, the same deck in the same seat: without it there is no saying what the rules did. When a bot ships, the bot league is played again with it (a new list, `bots-v2`, through `league-run`) for the standings among bots. The table above is the old exam, three stock seats; it is the record of how the four were chosen. Two things to keep in mind with the new one: until 2026-11-12 the pool was four decks that all win by attacking, three of them token decks, and every result up to `ab-run` #25 was earned against that table; and in games played before harness 0.4.0 `playbook_stats` are summed over every playbook seat of a game, so at a table of bots they say nothing about one seat (since 0.4.0 `playbook_stats_by_seat` keeps them for each seat).

### What the human figures are worth, and where the bots are going (the owner, 2026-11-11)
The owner had taken the human data for games recorded turn by turn, and on learning what it is called it effectively useless as a measuring stick. Checked, and mostly right (DESIGN §25, §26):
- What we hold is aggregates copied from Playgroup's public pages. No game, no turn, no action; every turn-by-turn log in this project is the sim's own.
- A precon's human win rate is how often people won with that exact list against unknown decks that were on average stronger than a precon (the 92 precons average 21%, not 25%). A typical figure is good to five points either way; over half the spread of the table is sampling noise; a second sample of the table would agree with it at a rank correlation of about 0.45 and a perfect simulator at about 0.66 (the stock league's 0.266 was read against 1). The ends of the table are real, the order of the middle is not.
- So a human win rate does not grade a bot: its rate at our tables is against our opponents, people's is against theirs. The figures were a way to pick decks (the ones stock AI plays furthest below their standing among people) and nothing finer. The table-level figures (rounds, mulligans, first seat) are over every deck people track, not precon tables.
- Playgroup records casts only for games on its own online table, keeps those games private and publishes per-card aggregates (drawn, played, turn of the first cast). `runner/cardplay.py` computes the same from our logs and twelve cards are in `runner/reference/playgroup-cards.json`; they showed nothing about the unplayed answers that the logs had not shown already. The file stays and is not extended.
- The yardstick is built from our own games: the paired control at tables of bots; mistakes that need no human to define, counted in the logs (a loss with a castable answer in hand, mana unspent beside castable cards, permanents never activated, cards drawn and never played; not written yet: lethal not taken, the unblocked attack that killed the seat with blockers at home); and the owner reading games (`runner/hands.py game` prints one seat's game turn by turn).

The owner's direction, the same day: this ends with the custom bots handling every step. That day a playbook answered four of the 108 differently named questions Forge puts to a seat's controller (`declareAttackers`, `chooseSpellAbilityToPlay`, `confirmTrigger`, `mulliganKeepHand`). Since 2026-11-21 the owner's ten answer two more in part (`declareBlockers`, when Forge's blocks leave the seat dead; `orderAndPlaySimultaneousSa`, for the target of a removal trigger); modes, what to sacrifice or discard, payments, most targets, and everything on another player's turn are stock Forge's. A step taken over stays per deck (a hook in `PlaybookController` that is inert until a deck's playbook names it) and earns its place at the tables like a rule does. The session's proposed order of 2026-11-11 was answers, blocks, targets and modes as an effect resolves, responses on other players' turns, mulligans; since 2026-11-20 the order follows the counted mistakes (Next).

### What the measurements settled
- The deck's own lines are the lever: cast and trigger rules moved four decks by 8 to 12 points. Whom the seat attacks moved nothing by itself (`ab-run` #6), and the blocker-counting `pressure` attack lost to `go_wide` on three decks at tables of stock AI and tied with it on the fourth (Hail, Caesar, 45 wins against 44). At tables of bots `go_wide` lost to Forge's own attack on the pool of four and beat it on the pool of twelve for the three decks that carry answer rules (below), and two of those, Hail, Caesar and Tricky Terrain, attack go-wide again since 2026-11-13; `pressure` stays in the code unused.
- The twelve hold up among each other (`ab-run` #26, DESIGN §28): at tables drawn from the other eleven bots the playbooks win 557 of 2,400 tables and the stock pilots of the same decks 419, nine decks ahead, one level, two a point or two behind; four leads are clear of noise. A deck's figure on one pool says little about the next (Limit Break +11.5 on the pool of four, +2.5 among the twelve; Enduring Enchantments level, then +11.0).
- There is no shortcut to 91 playbooks: a mechanical draft (`runner/playbook.py draft`) gains nothing in goldfish on three decks and under half the hand-written rules' gain on a fourth. Decks are picked by an audit of what stock leaves undone and their lines are written by hand.
- Goldfish (minutes) says whether a seat runs its engine, not what that is worth: two turns of speed bought Goblin Storm eleven points and Quick Draw three and a half. Duels misjudged Tricky Terrain. Forty tables and sixty duels were right that the candidates beat stock and wrong about which candidate is best.
- What a bot is, and is not (DESIGN §23, `runner/losses.py` on the 800 games of `ab-run` #17): its rules make two thirds to four fifths of the seat's spell casts and two fifths of its attack declarations. Everything about the other three players is still Forge's and measures the same as stock: under one spell a game aimed at an opponent, one attacker in six blocked, the same mulligans, and a loss that comes within a turn cycle from one opponent with three castable cards in hand.
- A table of the four bots plays a 39-turn game where the same seats under stock play 54 (20 and 17 games on a session's machine; 9.75 rounds against 13.5 by the scorecard's turns over four, people 8.75). Game length follows the pilots (in Actions since: the bot league's 10.3 rounds, DESIGN §24). Most of that was the go-wide attack: with the attack left to Forge the league of twelve plays 45.9 turns, 11.5 rounds, two turns under a stock league's 48 (`league-run` #3, DESIGN §28; other decks, so a reading across runs).
- At tables of bots the attack policy was giving back most of what the rules earned (`ab-run` #19 and #23 to #25, DESIGN §27). Thirteen decks played the same rules with `go_wide` and with Forge's own attack on the same 200 tables: not one won fewer tables with Forge's attack, and summed over 2,600 tables the stock pilots won 501, the rules with `go_wide` 567 and with Forge's attack 685. The first reading of #19, that a faster engine does not win among bots, was wrong: Deep Clue Sea's rules are worth twelve points there once the attack is Forge's. `go_wide` was chosen at tables of stock AI, where an open board is not punished.
- The attack is not settled (`ab-run` #26, DESIGN §28). On the pool of twelve, with their answer rules, Hail, Caesar, Tricky Terrain and Goblin Storm each won more tables with `go_wide` than with Forge's attack on the same 200 tables: 66 against 45 (exact test 0.0046), 58 against 40 (0.027), 56 against 47 (0.26). Token Triumph and Quick Draw, which have no answer rules, lean to Forge's (65 against 54, 50 against 43). The rules and the pool both changed since the pool of four, and the round cannot say which turned it. A deck's best attack depends on its rules and its table: the case for an attack written per deck, against any default. The ten engine-only candidates of the owner's table read like the pool of four again (`ab-run` #27 to #30, DESIGN §30): eight of ten won more tables with Forge's attack, 588 against 542 over 2,000 tables (247 discordant tables against 201, exact test 0.033), no deck clear of noise by itself. The second pass of the owner's ten, which all carry answer rules, reads the same way (`ab-run` #36 to #39): nine of ten won at least as many tables with Forge's attack, 647 against 606 over 2,000 (242 discordant tables against 201, exact test 0.057); Ahoy Mateys is the exception (72 against 64). So answer rules are not what makes go-wide better: that was three decks on one round. Forge's attack is what a new playbook starts from, go-wide an arm to try on the same tables, and goldfish does not say which (every one of the ten is half a turn to three quarters of a turn faster in goldfish with go-wide).
- Where a table's attention goes is Forge's, and it reads the same at stock tables and among the twelve (`runner/heat.py`, DESIGN §28): 72 to 76% of attackers go at the opponent with the most nonland permanents (chance 40%), 52 to 57% at the lowest life, 52 to 55% at the one opponent who attacked the seat last turn; the player who goes on to win receives 22% (chance 37%). Aimed spells and abilities (3.3 to 3.5 a seat a game, a third to two fifths of them spells) follow the same order more weakly. Forge piles on the widest board and the weakest player; it does not see who is winning. This is the baseline for any judgement of danger written here.
- Answer rules are worth what the seat's position makes them worth (`ab-run` #21, DESIGN §27): wipes that the shipped bots cast in a fifth to two fifths of the games they drew them are cast in three fifths to three quarters under the rules, which gave Hail, Caesar 9.5 points, Goblin Storm 4, Tricky Terrain a lean and Token Triumph, the deck that led that table, nothing.
- Engine rules crowd out the rest of the deck (2026-11-14, DESIGN §30). In the seat's own main phase a rule that has something to do always goes before any card the rules do not name, so a playbook of engine rules casts its draw spells and ramp far more than stock AI and its removal, wipes and large threats far less: on the same 200 tables Blight Curse's candidate casts Incremental Blight in 10 of the 54 games it is drawn where stock AI casts it in 49 of 56, and the same shape shows in all four of the owner's decks examined so far, the one that is eight points ahead of its stock pilot included. Goldfish cannot show it and rewards it. `runner/playtest.py` on each arm and `docs/agents/arm_card_diff.py` on the pair are the check; run them on every candidate's exam before it ships, and give every card on the "cast less" list a rule. The second pass of the owner's ten did that (rules for 98 cards over the ten decks), and those cards are cast in 72% of the games they are drawn against the stock pilots' 70%; the better arm went from 98 tables ahead of the stock pilots over the ten decks to 157 (other tables, so a reading across runs), most of it in the three decks the first exam had behind (Blight Curse, Deadly Disguise, Miracle Worker).
- Forge's AI casts most of its permanents after combat, and a playbook's rules spend the mana before it (2026-11-14, DESIGN §30; the trial of the `forge` rule, `ab-run` #34). On the turns they attacked, the stock pilots of four decks cast 1,334 spells before the attack and 3,238 after it; the engine-only candidates 5,235 and 633. The `forge` rule asks Forge in the first main phase, where it declines the cards it keeps for the second, so the rule gives back the cards stock AI casts before combat (Incremental Blight 54 of the 63 games drawn, from 10 of 54) and not the ones it casts after (Dire Fleet Ravager 5 of 60 against stock's 41 of 50; Liliana, Binding the Old Gods, most creatures): a fifth to a half of what was crowded out, and 213 wins against 195 over 800 tables (exact test 0.23). A `play` rule that names a card casts it whenever it is read, so hand-written rules do not depend on this; the mechanical remedy does, and so does a list with swapped cards played under a precon's playbook. `runner/hands.py` has no phase to go by: a cast's place before or after the seat's `attack` event is the measure.
- A lead measured on the tables that chose the file halves on tables that did not (2026-11-15, DESIGN §32): the owner's ten were 157 tables ahead of their stock pilots over 2,000 in the exams they shipped on (the better of two attacks each) and 72 ahead at the owner's table. The abilities report had hidden this: it counted Kaust's own trigger as uses (111), and is corrected.
- Who is winning can be read off the table, and Forge reads it backwards (DESIGN §33, `docs/agents/leader.py` on 4,418 games): with three or four players alive the seat with the highest life goes on to win from 39% of all turns (48% from round 10), the widest board from 32% (40%), life plus twice the nonland permanents from 42% of the turns of rounds 7 to 9 and 52% later, chance being 26 to 29%; the lowest life wins from 16%. Forge's attackers go at the lowest life (49%) and the widest board (69%). No other count improves on that sum (2026-11-21, `docs/agents/danger_eval.py` on the 2,000 baseline games, scored on held-out games: creatures' power, lands, cards in hand, damage dealt and a model fitted over eight counts all land within a point of it), so the hooks' judgement of danger stays as it is.
- A card no pilot casts is cast once a rule can name and aim it, and that is all it takes (`ab-run` #43, DESIGN §33): Maelstrom Pulse in 49 of the 53 games it was drawn, Atomize 26 of 30, New Blood 47 of 49, Marauding Raptor 68 of 68, Toxic Deluge 15 of 39 under conditions about the board, each from none. One card moves a deck's wins by a table or two (the four that shipped: 219 against 211), so this is about playing the deck as a person would, not about win rate.
- Moving a rule up does nothing unless what stands above it is what starves it (`ab-run` #43): Blight Curse's large creatures above its draw spells were cast 3.3 points more often (51.9% of the games drawn against 48.6%; the stock pilot 80%), Revenant Recon's 0.9 points. - A trade of one group of casts for another comes out level in wins, every time it has been tried (DESIGN §32, §33): the `forge` rule's wait (211 against 219 over 800 tables), Blight Curse's creatures above its draw spells (35 against 35) and above its engine (39 against 37). What a playbook casts less than its stock pilot is a matter of how the deck is played, not a reserve of wins: the "cast less" lists are not worth a round of their own. A card nobody casts at all is another matter (the bullet above), and so is a wipe: Revenant Recon with Toxic Deluge lost five tables to the version without it (47 against 52, inside noise; 103 against 107 with the other candidate that carried the rule), so a wipe wants a deck it suits, not just a rule that can cast it.
- The aim goes where it is told and the removal bites (`ab-run` #43, a reading, not a paired measurement): of 122 aimed casts 101 went at the opponent that looked most dangerous and 21 at the next that had something worth four, none fizzled, 47 hit a commander; in the 80 games the caster did not win, the player who was hit went on to win 30 (38%), where the most dangerous opponent left alone wins about half of such games.

- A bot leaves alive a player it could have killed, and is mostly right to (`ab-run` #45, DESIGN §34; this bullet first said the opposite, from 20 local games). Under the shipped playbooks a seat passes up 34% of the turns on which it is sure to kill an opponent: 5% when it is the last opponent, 13% when it is the most dangerous of several, 53% when it is a less dangerous one. A weaker opponent left alive is worth something to the seat. The reading by situation was made after the result and wants tables of its own.

It won none of them: the block buys a turn or two (31 turns over the fifteen) in a game already going badly.
- How Forge's AI attacks, read from its source and counted (2026-11-21, DESIGN §34). It weighs an attack against one opponent: `choosePreferredDefenderPlayer` scores each opponent by the value of its board plus, once it is under 20 life, the square of what it is under by, draws one of the top scores, and decides everything else (who attacks, how hard) against that opponent's blockers alone. Counted on the 2,000 baseline games: with three opponents alive 48% of a table's attackers go at the opponent that looks most dangerous (a third by chance), and when none does, the one attacked has the lowest life at the table three times in four, though the most dangerous one is at least as open in seven declarations of ten. And an opponent who cannot block is attacked on 28% of the turns it could be; on 38% the seat attacks only an opponent with blockers, on 34% nobody (`runner/mistakes.py` splits it). Two hooks came of it (`"aim": "danger"` and `"open": true` on the attack, harness 0.4.5).

A guard that asks the one-opponent question repeats it: the guard's two arithmetics, replayed on the 125 deaths they were built for, changed the same six attacks. What Forge's check lacks is the opponents one after another, and what is not on the table yet.
- The removal a rule names is cast in the seat's own main phase (`docs/agents/other_turns.py --cards`, the seat under test in the 2,000 baseline games): 2,016 of 2,635 instants on its own turn before its attack, 521 on another player's turn, and those are the ones no rule names (Otherworldly Gaze, Arcane Denial, Telling Time). A seat that dies in combat on another player's turn held an instant in 305 of 1,141 such games, seldom removal. That is the shape of the missing reactive half.
- On other players' turns the bots are Forge's AI, and less of it (`docs/agents/other_turns.py` on the 2,000 tables of `ab-run` #42, the seat under test; this file said "they do nothing on another player's turn", which was wrong). The rules cast an instant in the seat's own main phase when they read it, so the playbooks made the seats a little less reactive than they found them. A person holds most instants for other players' turns. The size of it in these decks: one or two instants a game.
- The sure kill of the most dangerous opponent is worth taking, confirmed on tables that did not suggest it (`ab-run` #46, DESIGN §35): with `"finish": "leader"` the owner's ten won 516 tables of 2,000 where their shipped arms won 498 (32 tables only the hook won against 14, exact test 0.011), 21 against 5 on the 121 tables where that kill is the first thing that differs (0.0025; #45's reading after the result had 14 against 2), and the seat misses that kill on 5% of the turns it is there where it missed it on 14%. - Free damage is worth different things to different decks (`ab-run` #49): Blood Rites 77 wins against 60 (27 tables against 10, exact test 0.0076) and Ahoy Mateys 71 against 60 (0.052); Deadly Disguise 20 against 28, Veloci-Ramp-Tor 73 against 79, Squirreled Away 35 against 40. - Starting runs: the session's GitHub access cannot dispatch or cancel workflows (403; do not work around it). `runner/queue/ab-run.json` pushed to `testing` starts `ab-run` (`runner/queue/README.md`); the click-only workflows (`pod-run.yml`, `league-run.yml`) need the owner.

And `docs/agents/unfinished.py` on the base arm: the games without a winner, by what they ended in. List them for the run id (GitHub MCP `actions_list`, `list_workflow_run_artifacts`): two per shard, and `ab-rollups` once everything is done, which unzips to `ab-<deck>/rollup.json`. The listing is newest first, so `perPage` 1 answers both questions for a few hundred tokens: `total_count` says how far the run is, and when it is done the one artifact shown is `ab-rollups`. `python3 -I docs/agents/exam_summary.py <unzipped dir> --out demo-data/ab/<date>-ab-vNN` copies the rollups, joins the side arms of a deck on the same tables and prints every arm and paired difference. `actions_get` `download_workflow_run_artifact` gives a short-lived URL to curl into the scratch directory. 200 tables of two arms in ten shards take about an hour.
